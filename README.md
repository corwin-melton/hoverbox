# hoverbox

A visual field guide to UI elements: abstract illustrations, real-world
examples, and tags for finding the name of the thing you're picturing.

> **Status:** Work in progress. This README is a directive for the project,
> not documentation. Nothing is built yet.

---

## The idea
A website that's a visual reference for UI elements: tooltips, popovers,
context menus, drag badges, and everything else. Something to use while
designing apps and websites, both to find the name of a thing I'm picturing
and to explore what options exist.

## What I know I want
- Abstract, simplified illustrations of each element, some of them animated.
- Tags on everything, so the collection can be explored in different ways:
  graphs, trees, dichotomous keys, or whatever turns out to work best for
  finding what I'm thinking of.
- Lots of real-world examples attached to each abstract element, labeled with
  things like time, OS, app, and context, with photos.

## Areas to explore

### Discovery: what already exists
Look at existing sites in this space before designing anything, so hoverbox
does something they don't.
- What's out there? Starting points: component naming references, pattern
  libraries, design-system docs, and screenshot galleries of real apps.
- What does each do well, and where does it fall short?
- What gap is hoverbox filling?

### Findability and SEO
The site should be findable by people who don't know it's called hoverbox,
or even what the thing they're looking for is called.
- How does modern search work now, including AI-generated answers?
- How do people phrase searches when they don't know a UI element's name?
- How should pages, names, aliases, and descriptions be structured so
  those searches land here?
- What are the technical basics (metadata, structured data, performance,
  images) that matter?

### Execution: how it actually gets built
- Framework and site structure
- Hosting and whether servers are needed at all
- Where content, images, and examples live, and how I add new ones
- Search, filtering, and the interactive views (graphs, keys, trees)
- Animation approach for the illustrations
- Costs and maintenance

### Still open
Everything else: structure, tags, visual style, how browsing works, scope,
and where to start.
